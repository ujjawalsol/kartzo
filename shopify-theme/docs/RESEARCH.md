# KARTZO — Shopify Requirements Research (verified Oct 2026 from official docs)

Legend — applicability: **A** = working custom theme on own store · **B** = best practice ·
**C** = Theme Store submission only · **D** = needs specific plan · **E** = needs merchant config/app/infra.

| # | Source URL | Rule | Applicability | Implementation consequence |
|---|------------|------|---------------|----------------------------|
| R1 | https://shopify.dev/docs/storefronts/themes/architecture | Theme = standard dirs (`assets blocks config layout locales sections snippets templates`); only `layout/theme.liquid` is strictly required for upload. Subdirs beyond listed are unsupported; `assets/` is flat (no subfolders). | A | Theme scaffold uses exactly those dirs; `assets/hero/*.webp` flattened to `assets/hero-*.webp`; docs live in `shopify-theme/docs/` (non-shipped, removed before packaging if uploader complains). |
| R2 | https://shopify.dev/docs/storefronts/themes/architecture/templates | One template per page type needed; no templates are mandatory. | A | Only templates the store needs are created (index, product, collection, list-collections, search, cart, page, page.contact + alternates, blog, article, 404, password, gift_card, customers/*). |
| R3 | https://shopify.dev/docs/storefronts/themes/architecture/templates/json-templates | JSON templates = `{sections, order}` (+ optional `layout`, `wrapper`); max 25 sections / 50 blocks each; every non-app section referenced must exist; section needs `presets` to be addable in editor. Gift card CANNOT be JSON. | A | All storefront templates are JSON (editor-rearrangeable) except `gift_card.liquid`; every referenced section exists with presets. |
| R4 | https://shopify.dev/docs/storefronts/themes/architecture/sections | Sections = reusable merchant-customizable modules; go in `sections/*.liquid`. | A | All configurable page components are sections, not monoliths. |
| R5 | https://shopify.dev/docs/storefronts/themes/architecture/sections/section-schema | Schema = valid JSON with `name`, `settings` (supported input types only), `blocks`, `presets`, `enabled_on/disabled_on`; every setting id referenced in markup must be defined. | A | All schemas validated by script; no invented setting types or font-picker objects (regression E). |
| R6 | https://shopify.dev/docs/storefronts/themes/tools/cli | `shopify theme check`, `shopify theme dev` (needs store auth), `shopify theme package/push` (unpublished with `--unpublished`). | A | Check run in CI/static; `dev`/`push` documented as merchant steps (no credentials in repo). |
| R7 | https://shopify.dev/docs/storefronts/themes/architecture/templates/product/overview | Product pages use product object + `form type=product` (variant id + quantity); deep-link variants via `?variant=`. | A | `main-product` uses native product form; variant selectors update price/availability; no-JS fallback = full-page form submit. |
| R8 | https://shopify.dev/docs/api/ajax | Ajax API (`/cart/add.js`, `/cart/change.js`, `/cart.js`, `/search/suggest.json`, product recommendations) is theme-hosted only, unauthenticated, locale-aware via `window.Shopify.routes.root`; no customer/order data. | A | Cart drawer + quick-add + predictive search use Ajax with locale-aware routes; failures show toast + fall back to `/cart` page. |
| R9 | https://shopify.dev/docs/storefronts/themes/navigation-search/filtering/storefront-filtering | Storefront filtering (`filter.p.*`, `filter.v.*`) is the supported method; filters must first be created in admin; sort via `sort_by` param. Decorative controls that don't affect results are not acceptable. | A (+E for filter creation) | `main-collection`/`main-search` render `collection.filters` / `search.filters` from Shopify; sort `<select name=sort_by>` submits real params; active-filter pills remove/clear. |
| R10 | https://shopify.dev/docs/storefronts/themes/best-practices/performance | Optimize images (Shopify CDN `image_url` widths/`srcset`), don't lazy-load LCP image, defer non-critical JS, avoid render-blocking externals, avoid excess Liquid loops. | B | `theme.css`+`kartzo.js` deferred/preloaded appropriately; responsive `image_url` + `srcset`; no Tailwind CDN runtime; Google Fonts with `display=swap` + system fallback. |
| R11 | https://shopify.dev/docs/storefronts/themes/best-practices/accessibility | Keyboard-operable nav/drawers/modals, visible focus, labels + unique ids, accessible names for icon buttons, contrast, dialog focus trap/return, landmarks, `prefers-reduced-motion`. | B | Skip link, focus-visible ring, focus-trapped drawers/modal with Esc + focus return, aria-pressed/labelled icon buttons, reduced-motion CSS kept. |
| R12 | https://shopify.dev/docs/api/shopify-cli/theme (Theme Check) | Theme Check = static linter (Liquid, JSON, performance, accessibility hints). Passing ≠ production-ready. | B | Check results recorded; NOT used as sole readiness proof (regression F). |
| R13 | Theme Store requirements (Lighthouse thresholds, feature coverage, settings breadth) | Submission-specific bars for selling a theme. | C — NOT applicable | Explicitly NOT applied: no invented features to satisfy store review; personal-store scope only. |
| R14 | Checkout extensibility / checkout.liquid | Checkout is Shopify-hosted; `checkout.liquid` only on Plus; styling via Checkout & accounts editor. `checkout.html` prototype has NO theme equivalent. | A + D (Plus) | Original `checkout.html` NOT converted to a template; cart links to `/checkout`; limitation documented. |
| R15 | Customer accounts (new accounts + `<shopify-account>`) | New customer accounts (default) are mostly Shopify-hosted; legacy `templates/customers/*` only apply if classic accounts enabled. | A + E (account config) | Header links to `routes.account_url`; legacy `templates/customers/*` included as fallback; account/order-history UI documented as Shopify-controlled. |
| R16 | Markets / money formatting | Prices via `money`/`money_with_currency` filters; never hardcode currency symbols. | A | All prices use `money`; INR symbol comes from store currency, not markup (regression D). |
| R17 | Predictive search | `/search/suggest.json` powers suggestions; `predictive_search` Liquid object for SSR. | A | Search modal uses `suggest.json` (Ajax) with trending links + empty state; header forms submit to `/search`. |
| R18 | Product recommendations | `recommendations` object / `/recommendations/products` (Ajax) drives related products. | A | `product-recommendations` section uses Shopify recommendations with limit setting (regression C). |

Decisions: personal-store scope (A) + best practices (B) are binding; (C) ignored by design; (D)/(E) items are implemented as supported + documented with merchant setup steps.
